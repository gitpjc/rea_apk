## Verified shared controls

Captured models use nine words: enabled, model, Gain, Bass, Mid, Treble, Presence, Master and an opaque Boolean amplifier word. The six settings appear in that mobile order, use integer values 0–100 and have no inferred physical unit. The final Master control requires scrolling; every model is inspected at the top and bottom. Windows OCR reads only the authorized private iAMP phone captures to check those labels; unexpected labels stop the capture for manual inspection.

`AmpParameters.Models` is an explicit allowlist built from completed evidence in `tests/fixtures/f15-amp-model-observations.json`. `completeCatalog` is now true: all 55 models are captured and independently verified. Static names in the phone APK corroborate the catalogue, but do not establish parameter layouts or ranges. The fixture retains independent successful mobile frames, defaults and capture hashes without phone identifiers or Bluetooth addresses. Older independently captured PLX 100 ranges/on-off frames remain included.

The desktop uses the existing six Amp editors at the selected physical position. Different and identical Amp models retain separate pending values. An unchanged refresh preserves them. Disabled models show grey icons, readable values and Enable effect; edits require an enabled, supported layout. JSON uses the same six ordered settings, with null unit/group, retaining schema 3.0.0.

## Capture and restoration procedure

1. Force-stop only iAMP to release its Bluetooth connection. Independently read and compare the complete original amplifier state/detail before the next test; any difference stops the test without writes.
2. Open iAMP, wait for its connection progress to finish, then select Amp. Locate the intended model from the captured list and verify its row has stopped scrolling before selecting it.
3. Wait for the intended model's name to appear in its controls. A restarted iAMP can reuse replacement token 100; the amplifier can ignore that repeated token. One further UI selection is allowed only when iAMP's returned complete Amp block still equals the original. This is a bounded unchanged-state recovery, not a blind write retry.
4. Inspect the top controls, toggle off/on to retain the default full block, then capture 0 and 100 at each setting. Scroll to Master and capture its endpoints. Retain a final off/on pair.
5. A `finally` cleanup stops iAMP, reads fresh Windows state, checks all unrelated preset bytes and global state, restores the original PLX 100 and every original parameter, then reconnects independently to compare every original state/detail byte. Any capture or restoration failure stops the batch.

## Desktop verification

Focused protocol checks compare the encoder against independent mobile frames, exercise every integer at all twenty physical positions and reject unknown/disabled/malformed/out-of-range configurations. They preserve the opaque Boolean word and retain the existing narrow save guard. Offline WPF checks exercise all enabled model IDs, ordered sliders/JSON, invalid and pending inputs, different/identical model instances, refresh, unsupported firmware, disabled/re-enable states and absence of hardware access.

Actual Windows checks are prepared separately from phone captures. For each model they use the real window handlers to apply 0, 100 and the captured/default value to every control, test off/on, move position 3→2, edit and restore Gain there, then move back. Each model must finish with complete independent original restoration.
