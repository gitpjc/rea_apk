# Windows iAMP feature matrix

Updated: 13 October 2026. Windows BLE identity/capability and all 80 preset-name reads have succeeded on the connected V1.1.2 amplifier. The initial WPF read-only viewer is under construction; full editor acceptance remains pending.

## Evidence and completion rules

- M refers to `DOCO/MOOER/F15i Li_Manual_EN_V01_2025.06.19.pdf`, using **printed page numbers**. Add three to obtain the PDF page number in the referenced sections.
- N refers to `DOCO/MOOER/MOOER AMP.md` (user notes), and P to `DOCO/Codex/Plan.md` (engineering scope/design).
- A refers to retained APK evidence under `analysis/generated/`. Primary APK badging identifies `com.mooer.iamp`, version 1.6.1, version code 42; phone-extracted build is version 1.6.1/code 43. The builds share publisher identity but are not byte-identical.
- Execution placement below is a baseline interpretation of the documented workflow. Device commands, transport, numeric encodings, firmware differences and local/cloud boundaries still need runtime evidence.
- **I** means implemented and software checks passed; **H** means the specific row's hardware acceptance passed. Keep these separate. Narrow read-only rows below are complete; their parent editor workflows remain unchecked.
- R refers to `Protocol.md` and `Native-Findings.md`; W to private `analysis/private/windows-read-info.json` and Windows GATT discovery `analysis/generated/amp-gatt.json`. W establishes actual Windows reads; raw device evidence remains untracked. Five .NET protocol tests and five Node capture tests passed. Initial capture coverage comprises 233 attributed ATT PDUs and 79 CRC-valid frames.
- Add acceptance evidence (capture/fixture/test path and date), actual firmware and pass/fail result to each row when tested. A screenshot or simulator does not satisfy H. Purely local features use H to record the device round trip where relevant; purely visual features can record H as not applicable with a justification.

## Release gate

MVP requires parent rows F01-F11 acceptance, applicable hardware checks on a recorded Windows/adapter/firmware combination, a backup/recovery baseline, and the P5.8 musician workflow (connect, select, edit, save to chosen slot, reconnect, verify). Completed F03a/F08a information reads are incremental milestones and do not satisfy their full parent rows. Backup/recovery remains unrecorded and is required before mutation experiments. Unsupported advanced features remain explicit; neither a simulator nor a read-only snapshot viewer completes the editor workflow.
